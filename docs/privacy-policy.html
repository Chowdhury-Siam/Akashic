Yutaka Privacy Policy

Effective and last updated: 30 September 2026

Yutaka is a local-first personal finance application developed by Siam Chowdhury. Finance data is stored on the device first and only leaves the device when the user enables an online feature or explicit export.

Local-first operation

Yutaka can be used without a sync account. Local data can include accounts, balances, transactions, categories, budgets, loans and repayments, plans, subscriptions, notes, preferences, profile media, backups and reports.

Self-hosted sync

If enabled, Yutaka sends synchronized data to the Cloudflare Worker URL configured by the user and to the database connected to that Worker. Authentication can include a username, password-derived verifier, access/refresh tokens, device/session records, timestamps and version metadata. Yutaka does not operate a central finance-data sync server.

Profile media and files

Profile photos, GIFs and short videos are processed only after selection. They are stored locally and can be synchronized to the configured Worker. Imported, exported or shared files are handled by the location or service selected by the user.

Telegram and Google Drive

Telegram and Google Drive delivery are optional. The configured Worker can send requested backup/report files and stores supported Telegram/Google credentials encrypted with Worker-side keys. Files already exported remain subject to the external service and are not automatically deleted by Yutaka account deletion.

Optional analytics and crash reports

Firebase Analytics and Crashlytics are off by default. If enabled in Settings > Privacy & data, Firebase may receive app-interaction events, crash logs, diagnostics, app/device information and an app-instance identifier. Yutaka does not intentionally attach finance contents, passwords, sync tokens or integration secrets to telemetry.

Updates, fonts and network metadata

Google Play builds use Google Play for Android updates. Direct builds can contact GitHub Releases. Inter font resources can be fetched through Google Fonts when not cached. Network providers can receive ordinary connection metadata such as IP address and request time.

Permissions

Yutaka uses network, notification/alarm, boot/background, battery-optimization and user-selected media/storage capabilities for the corresponding app features. It does not request contacts, SMS, call logs, microphone or precise location. It has no advertising SDK and explicitly removes the Google advertising-ID permission.

Retention and deletion

Local data remains until removed from the device, app storage is cleared, or the app is uninstalled, subject to platform backup behavior. Self-hosted data remains until removed from the configured infrastructure. Authenticated self-deletion is available in the app. Users without the app can start deletion from Yutaka's public account-deletion page, which asks only for the self-hosted Worker URL and then redirects to that Worker's authenticated /delete-account form. Usernames and passwords are entered only on the user's Worker. Worker-side deletion does not erase local copies or files already exported to Telegram or Google Drive.

Security

Yutaka uses HTTPS for supported remote services, platform secure storage for supported secrets and encrypted Worker storage for supported integration credentials. Local finance data is stored in app-private storage. No system can guarantee absolute security.

Data sale and advertising

Yutaka does not sell personal or financial data and does not include an advertising SDK.
